# Candidate comparison prototype

Issue [#423](https://github.com/billion-app/billion/issues/423) has a development-only race comparison at `/candidate-comparison-preview`. Open that route in a development Expo build (web: `http://localhost:8093/candidate-comparison-preview` when Metro is running on that port). It is deliberately not linked from the production ballot: [#344](https://github.com/billion-app/billion/issues/344) has not approved publication policy.

The [screen](../apps/expo/src/app/candidate-comparison-preview.tsx) offers two-, three-, eight-candidate and sparse examples. Every name, election and source passage is fictional and labeled. Sources open the supplied fictional record in place; these are not citations to real candidate facts. Each section poses one explicit question for the whole roster. Sourced answer headlines lead the vertical cards; optional reviewed bus and roadworks pictograms distinguish proposal subjects without rating candidates. Matching council-request rows expose the shared funding proposal, and document icons identify source actions. Text carries the same meaning for assistive technology; Candidate identity and attribution remain beside the answer. The section selector changes all candidates together. Source identity and the passage appear when opened, and “About this comparison” explains evidence limits and publication status. All-empty sections show one common explanation, a compact full roster and an in-place section selector. Cards reflow with text size. Withdrawal remains visible and never removes a candidate from comparison.

The [pure UI model](../apps/expo/src/components/candidate-comparison/model.ts) separates attributed statements, records, analysis and questionnaire responses. A claim requires source references; an optional short answer headline must be reviewed against those same references. Every section requires a nonblank shared question. Missing questions, malformed identity or unsupported claims fail closed. The future editorial adapter must ensure each answer actually addresses the shared question; validation cannot establish semantic alignment. Missing evidence does not imply an opposing position or a negative record. Questionnaire non-response is explicit only when supplied; a missing questionnaire cell stays an evidence gap. Different priorities are not automatically classified as disagreement, and equal card sizes do not assert equal evidence quality.

## Integration gates

This is a UI projection, not a competing persistence or analysis contract. [#421](https://github.com/billion-app/billion/issues/421) owns reviewed evidence, stable candidate/race identity, versions, review dates, invalidation, corrections and the tRPC publication boundary. The future adapter must project only a complete, explicitly scoped roster and current published claims from that contract, retain each claim's attribution and citations, and preserve candidate ballot status. Reads must not generate analysis. Once that contract is published, integrate in a dependent PR rather than copying its pipeline here.

Before publication, #344 must approve permitted comparisons, evidence standards, correction rules and unequal-evidence treatment. An explicit disagreement must be established by reviewed source-backed claims, never inferred from missing evidence or party labels. [#343](https://github.com/billion-app/billion/issues/343) owns questionnaire invitation, authentication and equal treatment; this screen does not collect responses and comparison does not depend on receiving them. [#420](https://github.com/billion-app/billion/issues/420) owns office powers. The fictional fixture illustrates budget proposals but does not supply live office analysis.

Release still requires editorial signoff, real-reader testing that identifies a sourced difference, native large-text and screen-reader testing, and verification of the production ballot → race → reviewed comparison flow. A fixture render and automated review do not satisfy those gates. The production route shows only an unpublished notice, and the renderer also rejects production use.
