# List → Map width regression

The Expo DOM export wraps the reader in `#root { display: flex }`. Without an
explicit width, the reader uses its content width. Prop 37's “What does it
actually do?” List fills the phone, but Map shrinks to about 365 CSS pixels.
The reader now fills its parent and allows its contents to shrink within it.

`prop37.json` is the public graph retrieved from the production tRPC endpoint
on October 13, 2026. It is a frozen UI fixture, not an ingestion input.

Export the production iOS app using the release guide, then run from the repo root:

```bash
node evidence/trillion-map-sizing/verify-export.cjs /tmp/billion-map-fixed-export
```

The check loads the actual exported DOM HTML and bundle in mobile WebKit,
opens the reported Prop 37 node, and asserts full reader width through three
List → Map switches at both 390 and 440 CSS pixels. It supplies the native
props bridge; it does not mock the reader or its styles.

The original OTA export failed: 365.40625 pixels instead of 390.
The corrected export passed all six transitions. Screenshots are generated by
the check and were visually inspected. Expo typecheck and lint also passed.
Physical-device verification and a production OTA publish remain outstanding.
